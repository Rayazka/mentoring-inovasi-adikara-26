## Alur kerja

Ikuti CONTRIBUTING.md. Gunakan issue yang dependensinya sudah selesai, implementasikan acceptance criteria, lalu buat PR. Keputusan produk tetap terbuka sampai dijawab pemilik produk. P2 belum dijadwalkan untuk rilis acara.

## Sumber dan pemeliharaan

- Manifest terstruktur: scripts/github/backlog.mjs.
- Peta nomor/URL dan checkpoint publikasi: docs/github/issue-map.json.
- Pemeriksaan lokal: node scripts/github/backlog.mjs --validate.
- Preview indeks: node scripts/github/publish-backlog.mjs (tanpa mutasi GitHub).
- Publikasi/resume: node scripts/github/publish-backlog.mjs --apply.
- Verifikasi remote: node scripts/github/publish-backlog.mjs --verify.

Script memakai ID stabil dan checkpoint. Ia tidak menutup issue atau menetapkan assignee/deadline. Jangan gunakan ulang untuk menimpa checklist epic yang sudah dikerjakan; tinjau perubahan terlebih dahulu.

PRD, planning internal, desain, foto, seluruh aset sumber dan data mentor tetap privat/lokal. Repo hanya memuat kode dan workflow issues sesuai izin pemilik. Kontributor membutuhkan akses sumber terpisah untuk pekerjaan yang bergantung padanya.
